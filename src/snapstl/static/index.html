Add a printer

On the printer: Settings → Network → LAN Only Mode on, then Developer Mode on (Bambuddy needs both). The access code and IP address are on the same screen; the serial number is under Settings → Device. Give the printer a fixed address in your router so it doesn't change.

Slicing

Printers only print sliced plates. Either slice by hand — open the plate in Bambu Studio → Slice plate → Export plate sliced file and save it in the batch folder's Sliced folder under the same path and name (e.g. Sliced/Bases/{Ayra,pink}.gcode.3mf) — or set a slicer service and SnapSTL slices each plate when you push it.

Preset names exactly as in Bambu Studio (system presets), e.g. Bambu Lab A1 0.4 nozzle, 0.20mm Standard @BBL A1, Bambu PLA Basic @BBL A1. Parts stay where SnapSTL placed them.

      Daily workflow

      1. Orders → Upload report (.xlsx) — the webstore Order Reconciliation Report. Only Magicians_35 orders are kept. Uploading the same or a newer report never creates duplicates; it only updates statuses.
      2. Needs review — fix names with spaces, symbols or missing colour, then Approve. Use Skip for orders you don't want to make.
      3. Ready — tick orders (or use the column filters and Select all matching) → Create batch.
      4. Batches → Queue download — the helper in your MakerWorld tab generates each name, one at a time (watch it on Downloads).
      5. When the batch says Ready to build → Queue build.
      6. Push to queue on the built batch sends each plate to a printer's queue in Bambuddy (see Printers) — or Show in Finder, open the plates in Bambu Studio, check, slice and print by hand. Bases in white; names in the colour of their folder.
      7. When the plates are printed: Mark these orders printed (Push to queue panel) or the Bundled tab → Mark printed.

      Nothing starts by itself: you queue each batch for download and for building. Batches queued for download are worked through in order.

      • Re-download — fetches every model of the batch again from MakerWorld (e.g. after changing the license password or if a model looked wrong). The new downloads replace the saved ones. Then Queue build / Rebuild plates. Stop cancels a re-download and leaves the batch as it was.
      • Rebuild plates — makes the plates again from the downloaded models (e.g. after changing plate settings). A new Batch N folder is written; the old one stays.

      Orders whose model failed or didn't pass the fit check aren't printed; on a first build they go back to Ready.

      The SnapSTL Helper (Chrome)

      The helper is a small Chrome extension that does the MakerWorld part in your normal Chrome, where you're signed in. For each name it fills the model-maker page (NO AMS, the name, compartments from the scaling table, your font settings), presses Generate and sends the two files to SnapSTL.

      • Install once: chrome://extensions → Developer mode → Load unpacked → the helper folder (Settings → SnapSTL Helper → Show helper folder).
      • The helper works in one tab (the working tab) and only while it shows the exact model page from Settings → MakerWorld model page link. Click the helper icon → Open model page, or open the page yourself and click Use this tab. If that tab goes to another MakerWorld page, the sidebar says so and nothing is downloaded until it's back.
      • Keep that tab open, ideally in its own window — Chrome slows down hidden tabs.
      • If MakerWorld shows a security check in that tab, complete it; the helper waits and carries on.
      • The sidebar shows the helper's status. Pause downloads stops it after the current name.

      License password & watermark

      Without the model's license password MakerWorld adds a watermark (for this organizer: raised "SALE NOT PERMITTED" text on the back of the base). SnapSTL makes sure that never reaches your plates:

      • No password, no download. Queue download / Re-download are refused until the password for this model is entered in Settings. A batch made earlier picks up the password automatically.
      • The helper confirms the password before and after Generate. It types the password first and again last, waits for the page to take it, checks the box still holds it right before pressing Generate and right after, and watches the page's own Generate request for it. If any check fails, the download is not saved and is tried again (3 tries).
      • Every download is scanned. If the watermark is still on the base, the download is not saved and is tried again. The Downloads page has a Watermark column.
      • Every build checks again. A base with a watermark is held back and its order returns to Ready; the batch says "Watermark check: found on N".
      • See it yourself. Open a batch → Objects: a picture of the back of every base (watermark painted red), click it for the top view, and Re-download any single object. Then press Rebuild plates — it waits until re-downloads are in, so the plates use the fresh files. Base plates are drawn from the top.

      The automatic scan knows this model's watermark. A different model may put a different watermark elsewhere — that's why downloads are refused without the password and the helper must confirm it; still glance at the pictures for a new model.

      Downloads

      The Downloads page shows the queue — every name waiting, being generated, done or failed, and which batch asked for it — with Pause and Retry failed.

      Downloaded models are saved in the Downloads folder (default ~/SnapSTL/Downloads, change it in Settings): one folder per name, e.g. SONAL - 5 comp - … with base.stl and name.stl exactly as MakerWorld made them. They're reused by every later batch and are never deleted by SnapSTL — clean them up in Finder (Show in Finder on the Downloads page). If you delete one, it's downloaded again the next time a batch needs it.

      Printers (print farm)

      Bambuddy, the open-source print-farm manager, is installed with SnapSTL on this computer (http://127.0.0.1:8000). It's connected to your Bambu printers and keeps a queue per printer. SnapSTL connects to it by itself; the Printers page shows it.

      1. On each printer: Settings → Network → LAN Only Mode on, then Developer Mode on. Note the IP address and access code (same screen) and the serial number (Settings → Device). Developer Mode disconnects the printer from Bambu Cloud and the Handy app.
      2. Printers → Add a printer: name, model, IP, serial, access code, and what it makes — Bases or Names (with the colours loaded, e.g. pink, blue). Bambuddy checks the connection first. The access code is kept by Bambuddy only.
      3. When you change a spool, update that printer's colours and press Save.

      Push to queue (Batches → open a built batch) lists every plate with a suggested printer: base plates → Bases printers, name plates → Names printers that have that colour, least busy first. Printers that don't fit are greyed out with the reason. Pushed plates go to that printer's queue in Bambuddy; the Status column follows them: Waiting to send → Slicing → Sending → In Bambuddy queue → Printing → Printed. A plate already on its way isn't pushed twice; Try again / Cancel are on each row.

      Clear plate: Bambuddy starts each next print only after someone confirms the bed is empty — the Clear plate button on the Printers page (or in Bambuddy).

      Slicing: printers only print sliced plates. Either slice by hand — open the plate in Bambu Studio → Slice plate → Export plate sliced file → save it in the batch folder's Sliced folder under the same path (e.g. Sliced/Names/pink/{Ayra,pink}.gcode.3mf) — or set a slicer service (Bambuddy's slicer sidecar, Docker) on the Printers page and SnapSTL slices each plate as it's pushed, without moving any part. The plate list shows Sliced / Not sliced.

      Fit & scaling

      Every organizer is resized to a target length and height by letter count (Settings → Scaling). The name piece always gets exactly the same length and height factors as its base (Name X = Base X, Name Y = Base Z; thickness 50 %), so it keeps MakerWorld's proportions and fits the base after printing.

      Fit check: for every order SnapSTL checks that the name's size relative to its base (length % and height %) is unchanged — once after scaling and again by measuring the .3mf files it wrote. A pair that fails is not printed: it's left out of the plates and its order returns to Ready. The batch page shows "Fit check: N/N", and report.csv lists name_vs_base_length_%, name_vs_base_height_% and fit_check per order.

      A name and its base are always built in the same batch with the same settings — don't print a name from one batch with a base from another after changing scaling settings.

      Settings

      • Model maker options — font, font size, thickness, outline, rotate text; same for every name. Changing them makes new models (old ones stay cached).
      • MakerWorld model page link — the model-maker page the helper must be on (its designId is checked). License password for this model — removes the anti-sale markings; each model keeps its own password (saved in SnapSTL's settings on this computer).
      • Scaling and compartments — target length/height and compartments per letter count (Scaling Rules v1.1).
      • Plate and fit — bed size, edge margin, gap between parts, names/bases per plate, allowed rotations (flat on the bed only).
      • Output folder — where dated batch folders go. Downloads folder — where downloaded models are kept. Pause between downloads — seconds between names.
      • Database — back up, clean up old records (orders already made are always kept), or reset. None of these delete files.

      Using SnapSTL from other computers

      SnapSTL is a small web server running on this computer (the main computer). The main computer keeps the service running and has the SnapSTL Helper in its Chrome with the MakerWorld model page open — downloads always happen there.

      1. On the main computer: Settings → Other computers → tick Allow other computers on this network, set a portal password (10+ characters) → Save. SnapSTL restarts; if macOS or Windows asks to allow incoming connections, click Allow.
      2. The card then shows the address, e.g. http://snapstl-mac.local:8317 or http://192.168.1.20:8317.
      3. On another computer on the same network: open that address in any browser and sign in with the portal password.

      From other computers you can upload reports, review orders, create and queue batches, and download plates (click a plate, or Download ZIP). Only the main computer can: run the helper, use the Finder / File Explorer buttons, change folders, the model link and its license password, turn the portal on/off, and reset the database. Turn the portal off again to keep SnapSTL to this computer only.

      Your data

      Settings and backups are on this computer (Mac: ~/Library/Application Support/SnapSTL, Windows: %LOCALAPPDATA%\SnapSTL). Downloaded models: your Downloads folder. Plates: your output folder. SnapSTL never deletes downloaded models or batch folders — you clean them up yourself. Orders (with customer names, phones and addresses) are in this computer's own database, and — when connected in Settings → Shared order records — batched, bundled and printed orders also in your shared order records in Supabase (Settings → Database says which). SnapSTL runs in the background (it starts at login); the window is just a view — you can also open http://127.0.0.1:8317 in a browser.

      Several computers (shared order records)

      With the shared order records set up (Settings → Shared order records), every computer works in its own database, and every order taken into a batch, bundled or printed is recorded in Supabase. Creating a batch claims its orders there first: an order another computer already has is left out and shows in Batch N · computer. Bundled, printed and released orders and newer webstore statuses are sent right away and every minute; Settings → Database → Sync now sends and loads everything at once. The records are never deleted, and Reset this computer's database doesn't touch them — Sync loads them back. Mark orders printed in the Bundled tab (tick them → Mark printed); they move to Printed and keep their batch.
