Slicing

Before a plate prints it's sliced into G-code by Bambuddy's slicer (its slicer service, e.g. in Docker next to Bambuddy), with the profiles stored in Bambuddy that you pick here for each printer model. SnapSTL keeps no slicing settings of its own — only which Bambuddy profile each model uses — and the sliced file stays in Bambuddy's library. Slicing runs in the background, one plate at a time; printing always waits for Start print.

    Bambuddy's slicer

    Each new plate is sliced for the printer pre-selected for it in Print, so it's ready when you press Start print. Off: a plate is sliced when you press Slice or Start print.

    Bambuddy profiles per printer model

    Every printer of a model slices with the same three Bambuddy profiles. Pick the model, then its profiles — every profile Bambuddy has is listed:

    Where the profiles come from

    Profiles are added and changed in Bambuddy, never in SnapSTL. Then press Reload from Bambuddy here.

    Your own profiles

    1. In Bambu Studio (or OrcaSlicer) save the printer, process and filament presets you print organizers with, then export them: File → Export → Export Preset Bundle (.bbscfg / .bbsflmt) or a preset's .json.
    2. In Bambuddy: Profiles → Local Profiles → Import Profiles, and drop the files there. They're listed here under Yours in Bambuddy.

    Cloud profiles

    Sign in to Bambu Cloud (or connect Orca Cloud) in Bambuddy; your cloud presets are then listed here too. For the Bambu Cloud list, the API key SnapSTL uses needs Allow cloud access (Bambuddy → Settings → API keys).

    Bambuddy's slicer service

    In Bambuddy: Settings → Slicer — turn on Use Slicer API and set the sidecar URL (or the SLICER_API_URL / BAMBU_STUDIO_API_URL settings of its Docker setup). Its Preferred Slicer decides whether Bambu Studio or OrcaSlicer slices.

    Good to know

    • The process profile must be made for that printer profile; otherwise Bambuddy's slicer fails and the plate says why.
    • Name plates are sliced in their colour, bases in white — one filament profile per model is enough.
    • Picking other profiles slices that model's plates again (automatically or at Start print); plates already printed aren't touched.
    • A profile deleted in Bambuddy makes slicing fail for that model until you pick another here.

    Print defaults per printer

    What each printer does when a plate starts. In Print you can change them for one plate (the Options column). Bambuddy's default leaves it to Bambuddy and the printer.

        Daily workflow

        1. Orders → Upload report (.xlsx) — the webstore Order Reconciliation Report. Only Magicians_35 orders are kept. Uploading the same or a newer report never creates duplicates; it only updates statuses.
        2. Needs review — fix names with spaces, symbols or missing colour, then Approve. Use Skip for orders you don't want to make.
        3. Ready — tick orders (or use the column filters and Select all matching) → Create batch.
        4. Batches → Queue download — the helper in your MakerWorld tab generates each name, one at a time (watch it in the Download queue on the same page).
        5. When the batch says Ready to build → Queue build.
        6. Print → Bases / Names: check the printer on each plate and click Start print — or Show in Finder on the batch, open the plates in Bambu Studio and print by hand. Bases in white; names in the colour of their folder.
        7. Orders → Ready to ship lists orders whose base and name are both printed; tick them → Mark printed (orders printed by hand: Bundled tab).

        Nothing starts by itself: you queue each batch for download and for building. Batches queued for download are worked through in order.

        • Re-download — fetches every model of the batch again from MakerWorld (e.g. after changing the license password or if a model looked wrong). The new downloads replace the saved ones. Then Queue build / Rebuild plates. Stop cancels a re-download and leaves the batch as it was.
        • Rebuild plates — makes the plates again from the downloaded models (e.g. after changing plate settings). A new Batch N folder is written; the old one stays.

        Orders whose model failed or didn't pass the fit check aren't printed; on a first build they go back to Ready.

        The SnapSTL Helper (Chrome)

        The helper is a small Chrome extension that does the MakerWorld part in your normal Chrome, where you're signed in. For each name it fills the model-maker page (NO AMS, the name, compartments from the scaling table, your font settings), presses Generate and sends the two files to SnapSTL.

        • Install once: chrome://extensions → Developer mode → Load unpacked → the helper folder (Settings → SnapSTL Helper → Show helper folder).
        • The helper works in one tab (the working tab) and only while it shows the exact model page from Settings → MakerWorld model page link. Click the helper icon → Open model page, or open the page yourself and click Use this tab. If that tab goes to another MakerWorld page, the sidebar says so and nothing is downloaded until it's back.
        • Keep that tab open, ideally in its own window — Chrome slows down hidden tabs.
        • If MakerWorld shows a security check in that tab, complete it; the helper waits and carries on.
        • The sidebar shows the helper's status. Pause downloads stops it after the current name.

        License password & watermark

        Without the model's license password MakerWorld adds a watermark (for this organizer: raised "SALE NOT PERMITTED" text on the back of the base). SnapSTL makes sure that never reaches your plates:

        • No password, no download. Queue download / Re-download are refused until the password for this model is entered in Settings. A batch made earlier picks up the password automatically.
        • The helper confirms the password before and after Generate. It types the password first and again last, waits for the page to take it, checks the box still holds it right before pressing Generate and right after, and watches the page's own Generate request for it. If any check fails, the download is not saved and is tried again (3 tries).
        • Every download is scanned. If the watermark is still on the base, the download is not saved and is tried again. The Download queue (Batches) has a Watermark column.
        • Every build checks again. A base with a watermark is held back and its order returns to Ready; the batch says "Watermark check: found on N".
        • See it yourself. Open a batch → Objects: a picture of the back of every base (watermark painted red), click it for the top view, and Re-download any single object. Then press Rebuild plates — it waits until re-downloads are in, so the plates use the fresh files. Base plates are drawn from the top.

        The automatic scan knows this model's watermark. A different model may put a different watermark elsewhere — that's why downloads are refused without the password and the helper must confirm it; still glance at the pictures for a new model.

        Downloads

        The Download queue at the bottom of Batches shows every name waiting, being generated, done or failed, and which batch asked for it — with Pause and Retry failed.

        Downloaded models are saved in the Downloads folder (default ~/SnapSTL/Downloads, change it in Settings → Folders): one folder per name, e.g. SONAL - 5 comp - … with base.stl and name.stl exactly as MakerWorld made them. They're reused by every later batch and are never deleted by SnapSTL — clean them up yourself (Show in Finder under the queue). If you delete one, it's downloaded again the next time a batch needs it.

        Print (print farm)

        Bambuddy, the open-source print-farm manager, runs on one Windows computer (as a service, with only its slicer service in Docker), for every SnapSTL computer (set up with bambuddy-server.ps1). Each SnapSTL connects to it in Settings → Connections with that computer's address, e.g. http://192.168.1.50:8000 — the sidebar's IP address line on the Bambuddy computer shows and copies it. Bambuddy is connected to your Bambu printers and keeps a queue per printer.

        1. On each printer: Settings → Network → LAN Only Mode on, then Developer Mode on. Developer Mode disconnects the printer from Bambu Cloud and the Handy app.
        2. In Bambuddy (Printers → Open Bambuddy): add each printer. Any printer can print bases or names — it only needs the right filament loaded.
        3. Filament is read from Bambuddy: every AMS slot and external spool with Bambu's colour name (Hot Pink, Jade White). Nothing to type in SnapSTL — load the spool and it shows up.
        4. Slicing: pick the Bambuddy profiles for each printer model (see Slicing below).

        Print (sidebar) has four lists. Bases: every base plate still to print, with the next available printer that has white loaded and the most filament left already chosen. Names: every name plate with its colour — only printers with that colour loaded can be chosen; one is pre-selected when available. Completed: printed plates, with Reprint only for a failed print. Removed: plates taken off the lists (e.g. printed by hand), with Put back.

        Each plate shows whether it's sliced for its printer's model (Sliced, Slicing, Slicing failed with the reason, or No profiles for A1 → Slicing). Options start from the printer's print defaults (Slicing → Print defaults); change speed, bed levelling, flow calibration or timelapse for that plate only.

        Nothing prints until you click Start print on a plate: that click slices it if needed, sends it to the chosen printer and starts it. Bambuddy prints it as soon as the printer is free and its bed has been cleared (Clear plate on the Printers page, or in Bambuddy). If Bambuddy warns (e.g. too little filament), SnapSTL asks before starting anyway. A printed plate moves to Completed; once an order's base and name are both printed it shows in Orders → Ready to ship.

        Printers

        Each printer in plain words: state and current print (progress, time left, layer, speed), temperatures and fans, filament per slot and AMS humidity, errors, network, SD card, door, nozzle, firmware and its queue in Bambuddy. Clear plate appears when a printer waits for its bed to be cleared. All fields on each card shows everything Bambuddy reports as it comes; Download JSON saves a copy; Farm activity lists what SnapSTL sent, started and sliced. Read only — access codes and keys are hidden.

        Slicing

        Every plate is sliced by Bambuddy's slicer (its slicer service, e.g. in Docker on another computer) for the printer it goes to, with the Bambuddy profiles picked for that printer model (all A1s share one set, all P1Ss another). SnapSTL has no slicer and keeps no slicing settings: only which Bambuddy profile each model uses. A model without picked profiles isn't sliced or printed, and Print says so.

        • Bambuddy profiles per printer model — choose the printer, process (layer height, walls, infill, speeds) and filament profile for each model. Every profile Bambuddy has is listed: yours in Bambuddy, Orca Cloud, Bambu Cloud and the slicer's standard ones. Reload from Bambuddy reads them again.
        • Adding profiles — in Bambuddy, never in SnapSTL: export from Bambu Studio (File → Export → Export Preset Bundle) and import in Bambuddy under Profiles → Local Profiles → Import Profiles; or sign in to Bambu Cloud / Orca Cloud in Bambuddy (the API key needs Allow cloud access for Bambu Cloud presets).
        • Bambuddy's slicer service — Bambuddy → Settings → Slicer: Use Slicer API on, with the sidecar URL. Its Preferred Slicer decides Bambu Studio or OrcaSlicer.
        • Print defaults per printer — speed, bed levelling, flow calibration and timelapse each printer uses at Start print (changeable per plate in Print).
        • Slice new plates automatically — each new plate is sliced for its pre-selected printer. A slice with no progress for 20 minutes is stopped with a message; a failed automatic slice isn't retried by itself (Slice again in Print).

        Fit & scaling

        Every organizer is resized to a target length and height by letter count (Settings → Scaling). The name piece always gets exactly the same length and height factors as its base (Name X = Base X, Name Y = Base Z; thickness 50 %), so it keeps MakerWorld's proportions and fits the base after printing.

        Fit check: for every order SnapSTL checks that the name's size relative to its base (length % and height %) is unchanged — once after scaling and again by measuring the .3mf files it wrote. A pair that fails is not printed: it's left out of the plates and its order returns to Ready. The batch page shows "Fit check: N/N", and report.csv lists name_vs_base_length_%, name_vs_base_height_% and fit_check per order.

        A name and its base are always built in the same batch with the same settings — don't print a name from one batch with a base from another after changing scaling settings.

        Using SnapSTL from other computers

        SnapSTL is a small web server running on this computer (the main computer). The main computer keeps the service running and has the SnapSTL Helper in its Chrome with the MakerWorld model page open — downloads always happen there.

        1. On the main computer: Settings → Connections → Other computers → tick Allow other computers on this network, set a portal password (10+ characters) → Save. SnapSTL restarts; if macOS or Windows asks to allow incoming connections, click Allow.
        2. The card then shows the address, e.g. http://snapstl-mac.local:8317 or http://192.168.1.20:8317.
        3. On another computer on the same network: open that address in any browser and sign in with the portal password.

        From other computers you can upload reports, review orders, create and queue batches, and download plates (click a plate, or Download ZIP). Only the main computer can: run the helper, use the Finder / File Explorer buttons, change folders, the model link and its license password, turn the portal on/off, and reset the database. Turn the portal off again to keep SnapSTL to this computer only.

        Your data

        Settings and backups are on this computer (Mac: ~/Library/Application Support/SnapSTL, Windows: %LOCALAPPDATA%\SnapSTL). Downloaded models: your Downloads folder. Plates: your output folder. SnapSTL never deletes downloaded models or batch folders — you clean them up yourself. Orders (with customer names, phones and addresses) are in this computer's own database, and — when connected in Settings → Shared order records — batched, bundled and printed orders also in your shared order records in Supabase (Settings → Database says which). SnapSTL runs in the background (it starts at login); the window is just a view — you can also open http://127.0.0.1:8317 in a browser.

        Several computers (shared order records)

        With the shared order records set up (Settings → Connections → Shared order records), every computer works in its own database, and every order taken into a batch, bundled or printed is recorded in Supabase. Creating a batch claims its orders there first: an order another computer already has is left out and shows in Batch N · computer. Bundled, printed and released orders and newer webstore statuses are sent right away and every minute; Settings → Connections → Sync now sends and loads everything at once. The records are never deleted one by one, and Reset this computer's database doesn't touch them — Sync loads them back. Mark orders printed in the Bundled tab (tick them → Mark printed); they move to Printed and keep their batch. Only orders taken into a batch are shared — Ready orders stay on the computer that uploaded the report. Show what's there lists what Supabase holds (in Supabase: Table Editor → schema snapstl). Clear shared records… (type CLEAR) empties them for every computer, after saving a copy in this computer's backups folder. Once a day, each computer also saves a copy of all shared records in its backups folder (shared-records-daily-…json, the last 30 days kept). Only SnapSTL can read the records: Supabase's public API has no access to them.
