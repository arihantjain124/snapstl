Nothing starts by itself. A batch moves to Archive once all its orders are on the way (or cancelled); 10 days later its folder goes to the Recycle Bin.

Slicing

Before a plate prints it's sliced into G-code by Bambuddy's slicer (its slicer service, e.g. in Docker next to Bambuddy), with the profiles stored in Bambuddy that you pick here for each printer. SnapSTL keeps no slicing settings of its own — only which Bambuddy profile each printer uses — and the sliced file stays in Bambuddy's library. Slicing runs in the background, one plate at a time; printing always waits for Start print.

    Bambuddy's slicer

    Nothing is sliced by itself: press Slice (or Slice all waiting) in Print to queue a plate for the printer chosen for it, or Start print slices it first if needed.

    Bambuddy profiles per printer

    Each printer slices with its own three Bambuddy profiles (printers with the same profiles share one slice). Pick the printer, then its profiles — every profile Bambuddy has is listed:

    Letters (name plates)

    Letter plates slice with this process profile and print at this speed on this printer; base plates use the profiles above. Once any printer has a Letters profile, letters print only on those printers — the others print bases. Print and Print next pick the right profile by themselves.

    Where the profiles come from

    Profiles are added and changed in Bambuddy, never in SnapSTL. Then press Reload from Bambuddy here.

    Your own profiles

    1. In Bambu Studio (or OrcaSlicer) save the printer, process and filament presets you print organizers with, then export them: File → Export → Export Preset Bundle (.bbscfg / .bbsflmt) or a preset's .json.
    2. In Bambuddy: Profiles → Local Profiles → Import Profiles, and drop the files there. They're listed here under Yours in Bambuddy.

    No cloud profiles

    SnapSTL slices only with profiles stored in Bambuddy itself — Yours in Bambuddy (Profiles → Local Profiles → Import) and the slicer's standard ones — so slicing never depends on Bambu Cloud. Bambu Cloud / Orca Cloud profiles aren't listed.

    Bambuddy's slicer service

    In Bambuddy: Settings → Slicer — turn on Use Slicer API and set the sidecar URL (or the SLICER_API_URL / BAMBU_STUDIO_API_URL settings of its Docker setup). Its Preferred Slicer decides whether Bambu Studio or OrcaSlicer slices.

    Good to know

    • The process profile must be made for that printer profile; otherwise Bambuddy's slicer fails and the plate says why.
    • Name plates are sliced in their colour, bases in white — one filament profile per model is enough.
    • Picking other profiles means a new slice for that printer's plates (press Slice again, or Start print slices it); plates already printed aren't touched.
    • A profile deleted in Bambuddy makes slicing fail for that model until you pick another here.

    Print defaults per printer

    What each printer does when a plate starts. In Print you can change them for one plate (the Options column). Bambuddy's default leaves it to Bambuddy and the printer. Plate type is the build plate the printer has on — plates are sliced for it (bed temperature, and the plate Bambuddy and the printer show); Profile's plate uses what the process profile says (often Cool Plate). Changing it slices that printer's plates again.

Click the helper icon → Open model page, or open the page yourself and click Use this tab. If that tab goes to another MakerWorld page, the sidebar says so and nothing is downloaded until it's back.
          • 
      
        • Keep that tab open, ideally in its own window — Chrome slows down hidden tabs.
          • 
      
        • If MakerWorld shows a security check in that tab, complete it; the helper waits and carries on.
          • 
      
        • The sidebar shows the helper's status. Pause downloads stops it after the current name.

        License password & watermark
        
    
        Without the model's license password MakerWorld adds a watermark (for this organizer: raised "SALE NOT PERMITTED" text on the back of the base). SnapSTL makes sure that never reaches your plates:
        
    
          
      
        • No password, no download. Queue download / Re-download are refused until the password for this model is entered in Settings. A batch made earlier picks up the password automatically.
          • 
      
        • The helper confirms the password before and after Generate. It types the password first and again last, waits for the page to take it, checks the box still holds it right before pressing Generate and right after, and watches the page's own Generate request for it. If any check fails, the download is not saved and is tried again (3 tries).
          • 
      
        • Every download is scanned. If the watermark is still on the base, the download is not saved and is tried again. The Download queue (Batches) has a Watermark column.
          • 
      
        • Every build checks again. A base with a watermark is held back and its order returns to Ready; the batch says "Watermark check: found on N".
          • 
      
        • See it yourself. Open a batch → Objects: a picture of the back of every base (watermark painted red), click it for the top view, and Re-download any single object. Then press Rebuild plates — it waits until re-downloads are in, so the plates use the fresh files. Base plates are drawn from the top.
          • 
    
        
    
        The automatic scan knows this model's watermark. A different model may put a different watermark elsewhere — that's why downloads are refused without the password and the helper must confirm it; still glance at the pictures for a new model.
        
  
        

  
        
    
        Downloads
        
    
        The Download queue at the bottom of Batches shows every name waiting, being generated, done or failed, and which batch asked for it — with Pause and Retry failed.
        
    
        Downloaded models are saved in the Downloads folder (default ~/SnapSTL/Downloads, change it in Settings → Folders): one folder per name, e.g. SONAL - 5 comp - … with base.stl and name.stl exactly as MakerWorld made them. They're reused by every later batch and are never deleted by SnapSTL — clean them up yourself (Show in Finder under the queue). If you delete one, it's downloaded again the next time a batch needs it.
        
  
        

  
        
    
        Print (print farm)
        
    
        Bambuddy, the open-source print-farm manager, runs on one Windows computer (as a service, with only its slicer service in Docker), for every SnapSTL computer (set up with bambuddy-server.ps1). Each SnapSTL connects to it in Settings → Connections with that computer's address, e.g. http://192.168.1.50:8000 — the sidebar's IP address line on the Bambuddy computer shows and copies it. Bambuddy is connected to your Bambu printers and keeps a queue per printer.
        
    
        If Bambuddy, Docker, the slicer service or OctoEverywhere stops, open SnapSTL on the Bambuddy computer: Settings → Connections → This Bambuddy computer — external services shows each one. Check now looks again, Start starts whatever is down (choose Yes if Windows asks), each has its own Restart, and Restart all restarts Bambuddy, the slicer and OctoEverywhere (Docker has its own Restart). Keep running (on by default) starts what stopped by itself every minute; it never restarts anything that's running.
        
    
          
      
        1. On each printer: Settings → Network → LAN Only Mode on, then Developer Mode on. Developer Mode disconnects the printer from Bambu Cloud and the Handy app.
          2. 
      
        2. In Bambuddy (Printers → Open Bambuddy): add each printer. Any printer can print bases or names — it only needs the right filament loaded.
          3. 
      
        3. Filament is read from Bambuddy: every AMS slot and external spool with Bambu's colour name (Hot Pink, Jade White). Nothing to type in SnapSTL — load the spool and it shows up.
          4. 
      
        4. Slicing: pick the Bambuddy profiles for each printer (see Slicing below).
          5. 
    
        
    
        Print (sidebar) shows on top the printers free for the next print (with the colours loaded) and beds to clear, and has Refresh from Bambuddy. It has five lists. Bases: To print — every base plate still to print, with the next available printer and its best-matching filament slot already chosen; Printed — base plates printed whose letters aren't all printed yet. Letters (the names): every letter plate with its colour, first those whose base is printed (print these now), then those whose base is still to print; a printer and the slot closest to that colour are pre-selected. Both lists have a search (name, order ID or batch). Any printer and any loaded slot can be chosen — the slot is what the print uses. Fix plates (only what was spoiled) are listed first.
        
    
          
      
        • Merge (Letters): tick letter plates of one colour that aren't started — fix plates too — up to 3 names in all, and press Merge onto one plate (other colours can't be ticked; more than 3 names is refused). Under the list, Available to merge suggests plates whose bases are already printed; ticking a plate whose base isn’t printed asks first. Merge runs once per press (a second press is refused). Remove works on every plate, merged and split ones too. The names keep their size (no scaling) and go onto one new plate in the newest batch's Merged/ folder; the single plates leave the list. Split back returns them while the merged plate isn't started. Group by colour lists every name plate by colour, so one spool can print them all.
          • 
      
        • Print label (Completed; Settings → Logistics → Shipping labels): keep ShopDeck's Process Orders open and signed in in Chrome. The SnapSTL Helper finds the order (an expired AWB is regenerated first), changes the courier to the first one offered from the list, waits a minute and presses Label; SnapSTL prints the label only if it matches the order exactly (order, AWB, items, names). A parcel with other products asks whether all items are ready. Sign-in needed → sign in, then Continue. Anything unexpected stops with the reason.
          • 
      
        • Split (Bases or Letters, not started): choose how many go on each part (e.g. 2 + 1); same size, saved in Split/. Splitting a bases plate splits its letter plates the same way, so the letters of each base part are on their own plate and can be printed once that base is done (a letter plate already started, printed, merged or split is left as it is). Join back on the bases joins those letters back too while nothing is started.
          • 
      
        • Verify: one card per name, once its letters and its base are both printed (Bambu reports them printed) — nothing goes straight to packing. Type your PIN once (Done / switch person when you leave; signed out after 30 minutes without a check): every check is saved under you. The owner gives each person a PIN in Settings → Staff; until anyone has a PIN, choose the name instead. Put the letters with their base and mark each: Good, Letter(s) spoiled (tap the spoiled letters on the picture), Whole name spoiled, Wrong colour or Base broken or warped, then Confirm – ready to pack (or Save – send problems for reprint) — a Saving… screen covers the card until it's done (a second press saves nothing twice). Each problem gets a small Fix plate with only what was spoiled, at the same size, at the top of Bases / Letters; it's printed and checked like any plate. Whole plate failed… (on a card, or in Bases → Printed / Letters → Printed) sends a whole printed plate back to print. A name fixed twice before shows a warning to check the model. An order moves to Orders → Printed – pack it only when its base and its name are both checked good; until then Orders shows Printed – waiting for check. Everything printed before 0.24 counts as checked (Before 0.24).
          • 
      
        • Completed: names checked good and not shipped yet — colour, order, batch, printer, who checked it and when, and had a fix. Filter by date or search; tick rows and press Packing slip for a printable list. Found a problem (e.g. while packing) makes a fix plate and takes the order back to Printing.
          • 
      
        • Removed: plates taken off the lists, with Put back and Printed by hand (sends it to Verify). A plate leaves this list once its orders are packed, shipped or cancelled.
          • 
      
        • Bed clear: SnapSTL never starts a print on a bed that may still hold a finished print. If the printer shows a finished print, Start print asks you to take it off and confirm the bed is empty (this also clears the plate in Bambuddy). If the printer is busy with another print, the plate waits held in its queue — press Start print again once that print is done and the bed is empty.
          • 
    
        
    
        Each plate shows whether it's sliced for its printer (Sliced, Slicing, Slicing failed with the reason, or No profiles for A1 → Slicing). Options start from the printer's print defaults (Slicing → Print defaults); change speed, bed levelling, flow calibration or timelapse for that plate only.
        
    
        Nothing prints until you click Start print on a plate: that click slices it if needed, sends it to the chosen printer and starts it. Bambuddy prints it as soon as the printer is free and its bed has been cleared (Clear plate on the Printers page, or in Bambuddy). If Bambuddy warns (e.g. too little filament), SnapSTL asks before starting anyway. A printed plate moves to Completed; once an order's base and name are both printed it shows in Orders → Ready to ship.
        
  
        

  
        
    
        Printers
        
    
        Each printer in plain words: state and current print (progress, time left, layer, speed), temperatures and fans, filament per slot and AMS humidity, errors, network, SD card, door, nozzle, firmware and its queue in Bambuddy. Clear plate appears when a printer waits for its bed to be cleared. All fields on each card shows everything Bambuddy reports as it comes; Download JSON saves a copy; Farm activity lists what SnapSTL sent, started and sliced. Read only — access codes and keys are hidden.
        
  
        
  
        
    
        Slicing
        
    
        Every plate is sliced by Bambuddy's slicer (its slicer service, e.g. in Docker on another computer) for the printer it goes to, with the Bambuddy profiles picked for that printer (printers with the same profiles share one slice). SnapSTL has no slicer and keeps no slicing settings: only which Bambuddy profile each printer uses. A printer without picked profiles isn't sliced or printed, and Print says so. (Profiles picked per model before 0.22.7 still apply to its printers until you pick their own.)
        
    
          
      
        • Bambuddy profiles per printer — pick the printer by name, then its printer, process (layer height, walls, infill, speeds) and filament profile. Listed: yours in Bambuddy (Local Profiles) and the slicer's standard ones — no cloud profiles, so slicing never depends on Bambu Cloud. Reload from Bambuddy reads them again. Each list has a search box: type any words from the profile's name or where it comes from (e.g. a1 0.4, 0.20 strength, pla matte, bambu cloud) — Enter picks the first match.
          • 
      
        • Adding profiles — in Bambuddy, never in SnapSTL: export from Bambu Studio (File → Export → Export Preset Bundle) and import in Bambuddy under Profiles → Local Profiles → Import Profiles; or sign in to Bambu Cloud / Orca Cloud in Bambuddy (the API key needs Allow cloud access for Bambu Cloud presets).
          • 
      
        • Bambuddy's slicer service — Bambuddy → Settings → Slicer: Use Slicer API on, with the sidecar URL. Its Preferred Slicer decides Bambu Studio or OrcaSlicer.
          • 
      
        • Plate type per printer (Print defaults) — the build plate on that printer (Textured PEI, Cool, Engineering, High Temp, Supertack, Textured Cool). Its plates are sliced for that plate, so the bed temperature is right and Bambuddy and the printer show the right plate. Profile's plate = what the process profile says (often Cool Plate). Changing it slices that printer's plates again.
          • 
      
        • Print defaults per printer — speed, bed levelling, flow calibration and timelapse each printer uses at Start print (changeable per plate in Print). The speed is set on the printer once it really prints (after heating and calibration), checked against what the printer reports and sent again if it didn't take; if the printer still won't change, the print says so.
          • 
      
        • Queues (bottom right of Print) — tabs Downloading, Building, Slicing and Printing: what's running or waiting first, then the last few finished, refreshed every 5 seconds. Hide shrinks it to one line with the counts; Show opens it again (remembered on this computer).
          • 
      
        • Slicing only when you ask — nothing is sliced by itself. In Print, choose the printer for a plate and press Slice: it joins the slicing queue (one at a time) with that printer's profiles, and the row shows the slice for the printer selected. Slice all waiting does the same for every plate with a printer chosen. Start print slices first if the plate isn't sliced for that printer yet. A slice with no progress for 20 minutes is stopped with a message.
          •

        Fit & scaling
        
    
        Every organizer is resized to a target length and height by letter count (Settings → Scaling). The name piece always gets exactly the same length and height factors as its base (Name X = Base X, Name Y = Base Z; thickness 50 %), so it keeps MakerWorld's proportions and fits the base after printing.
        
    
        Fit check: for every order SnapSTL checks that the name's size relative to its base (length % and height %) is unchanged — once after scaling and again by measuring the .3mf files it wrote. A pair that fails is not printed: it's left out of the plates and its order returns to Ready. The batch page shows "Fit check: N/N", and report.csv lists name_vs_base_length_%, name_vs_base_height_% and fit_check per order.
        
    
        A name and its base are always built in the same batch with the same settings — don't print a name from one batch with a base from another after changing scaling settings.

        Packing page (8002) and customer help (8003)
        Packing page (port 8002): only orders made and checked, oldest first, with Label Generated; a clubbed order shows once every name is made; Packed today to undo. Customer help (port 8003, its own password): search, status, tracking, notes, WhatsApp, name check, Express, cancel, remake, and Late – message first. Enable each in Settings → Connections with its password.
        On the Mac or Windows host, enable Settings → Connections → Packing page and set a password. Press Save to start hosting immediately. Employees open http://HOST-IP:8002 and sign in. Allow SnapSTL incoming connections in the Mac firewall, or TCP 8002 for the local subnet in Windows Firewall if needed.
        Employees can read, copy, filter and export orders, choose columns and save views. Refresh orders reloads the host's synchronized data; it also reloads every minute. Uploads, changes, batches, printers, slicing and settings are unavailable. The full app stays local on Mac and Windows.
        
  
        

  
        
    
        Your data
        
    
        Settings and backups are on this computer (Mac: ~/Library/Application Support/SnapSTL, Windows: %LOCALAPPDATA%\SnapSTL). Downloaded models: your Downloads folder. Plates: your output folder. SnapSTL never deletes downloaded models or batch folders — you clean them up yourself. Orders (with customer names, phones and addresses) are in this computer's own database, and — when connected in Settings → Shared order records — batched, bundled and printed orders also in your shared order records in Supabase (Settings → Database says which). SnapSTL runs in the background (it starts at login); the window is just a view — you can also open http://127.0.0.1:8317 in a browser.
        
    
        Several computers (shared order records)
        
    
        With the shared order records set up (Settings → Connections → Shared order records), every computer works in its own database, and every order taken into a batch, bundled or printed is recorded in Supabase. Creating a batch claims its orders there first: an order another computer already has is left out and shows in Batch N · computer. Bundled, printed and released orders and newer webstore statuses are sent right away and every minute; Settings → Connections → Sync now sends and loads everything at once. The records are never deleted one by one, and Reset this computer's database doesn't touch them — Sync loads them back. Mark orders printed in the Bundled tab (tick them → Mark printed); they move to Printed and keep their batch. Every order is shared: a report uploaded on any computer reaches Supabase right away, and Settings → Database → Sync on the Orders page loads every computer's orders. Show what's there lists what Supabase holds (in Supabase: Table Editor → schema snapstl). Clear shared records… (type CLEAR) empties them for every computer, after saving a copy in this computer's backups folder; Settings → Maintenance → Reset this computer's database… with also clear Supabase ticked (type RESET ALL) empties this computer and Supabase together. Once a day, each computer also saves a copy of all shared records in its backups folder (shared-records-daily-…json, the last 30 days kept). Only SnapSTL can read the records: Supabase's public API has no access to them.
